# Test responsibilities and remaining qualification

The test groups qualify different responsibilities:

- `test_health_contract.py` checks the source health schema, generated Python model and actual local API/static-file behavior. It makes no analysis readiness claim.
- `test_local_host.py` starts the real CLI on a loopback port, checks local HTTP/assets, stops its owned process, and restarts. It does not establish saved-investigation persistence.
- `contracts/health-types.test.ts` checks generated TypeScript constants, required fields and closed payloads. The runtime version pattern is checked by JSON Schema/Python, rather than inferred from TypeScript's string type.
- `test_synthetic_fixtures.py` checks the fictional inputs and hand-checkable expectations with the independent test reference. Passing this group establishes fixture consistency and policy-ID registry shape, not companion correctness. The registry does not certify a product parser or supported policies.
- `test_analytics_acceptance.py` exercises real population and complete-evidence HTTP operations against exact synthetic memberships, source rows, identities and typed refusals. Graph, comparison, time and scoring behavior now has separate executable suites; the historical empty skipped placeholders have been removed, not marked as passing release evidence. Product logic must not return golden answers or run `fixture_reference.py` as the application.
- `test_investigation_contract.py` checks the closed source schema and generated request boundary; actual API tests separately qualify semantic refusals and avoid relying on model coercion.
- `test_import_acceptance.py` exercises actual local workspace/source/inspection/mapping/population/evidence operations with byte-preserved fictional CSV inputs, strict refusals and a fresh app instance. Tests fail until those operations exist; fixture consistency and schema checks do not substitute for these operations.
- `test_import_contract.py` checks the generated import boundary and explicit wall-clock versus UTC record forms.
- `test_selection_acceptance.py` exercises real complete-case selection, frozen parents, independent chip supports, explicit unevaluable groups, guarded selected evidence and supplied graphs through HTTP. The graph's raw-boundary and clock policies are explicit; its consumer compatibility is qualified separately against the pinned renderer.
- `test_selection_contract.py` checks descriptive intents and coupled graph clock domains, separately from actual query behavior.
- `test_threshold_fixture.py` verifies the independent 3-hour/exactly-4-hour/5-hour/missing endpoint inputs and strict/inclusive expectations. It establishes fixture consistency only, not a measured product operation.
- `test_explorer_core_http.py`, `test_explorer_threshold_restart.py`, API case-list/start-trend/rule-group tests and analytical case-time tests qualify implemented descriptive time and complete-case explorer operations; these do not establish business resolution semantics.
- `test_comparison_acceptance.py` and `test_comparison_cohorts.py` exercise actual group/period comparison and exact cohort evidence; `test_scoring_acceptance.py` checks actual supplied Method values, applicability and witnesses, not an eligible released library.
- `test_saved_investigation_restart.py`, `test_saved_score_restart.py` and integrity/refusal suites qualify saved questions and original runs across processes and damaged state.
- `test_capacity_benchmark.py` invokes the real synthetic benchmark CLI, which measures HTTP operations, stops its host, copies/restores the whole workspace and verifies the saved selection/evidence/run through a new host. It also refuses invalid parameters and unsafe receipt destinations. It does not set timing thresholds or use company data.

Qualification of health/schema/build, synthetic reference arithmetic, actual analytical behavior, browser components and installed artifacts should be reported separately. No company data is included. See [current status](../docs/status.md) for coverage and explicit gaps: the matrix, eligible library releases, complete linked exploration, Windows human behavior and supported capacity remain open. jsdom and synthetic CLI tests do not qualify real-browser rendering or a Windows 11 analyst journey.

Acceptance inputs use named machine-readable IDs from `fixtures/incidents/policy_ids.json`. Text in `expected.json` describes the examples for readers; it must never be parsed as a policy language. Registry sanity checks alone do not establish actual parser or refusal behavior; executable operation tests must do that.
