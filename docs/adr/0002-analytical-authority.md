# Analytical authority and complete cases

**Status:** selected semantics; qualified feature by feature.

**Problem:** independently calculated counts, missingness and context make linked views disagree and mislead comparison.

**Decision:** canonical pure descriptive analytics owns complete-case selection, representation, graphs, matrix, variants, context and comparison measures. Method owns supported normative validation and scoring. Storage/SQL is a qualified execution adapter; the browser formats typed answers. Every linked answer has the same revision and meaning-bearing identity.

Freeze the eligible parent before splitting kept/removed. Keep semantic target/comparator roles distinct. Nullable measures expose an unevaluable population. Preserve opening missingness, distinguish literal values from missing keys, and declare ordered mapped sequences and source gaps. Show units, support and denominator for every measure.

**Alternatives:** redefining truth in each UI view or SQL query is rejected. Treating missing evidence as false/passed is rejected. Having Method own all descriptive queries by default would conflate two responsibilities.

**Consequences:** independent exact-ID and support tests qualify execution adapters and representations. A profile ratio is not an outcome-risk ratio; an association is not causation. Unsupported policies produce an explicit refusal rather than a guessed result.

**Normative scope and calibration:** platform predicates select descriptive case populations. Method alone evaluates a norm's applicability and returns scope/value/reasons. Selecting displayed cases selects scores from a named existing run; evaluating a subset creates a new run with its own calibration/population identity. Raw measurements, graded values and descriptive threshold partitions remain distinct.
