# 26: Check quantified recorded-event rules

Status: **proposed — owner seam/breakdown review pending; not yet a published ready-for-agent issue**.

## What to build

The analyst evaluates one named occurrence-quantified precedence/response rule, opens each activation and selected partner or violation, and compares occurrence-level results with affected-item support.

## Acceptance criteria

- [ ] Existential versus every-occurrence, direct versus eventual, vacuity, partner reuse/consumption and tie policies are explicit definitions.
- [ ] Recorded-event absence, invalid/unknown chronology and a known violation remain distinct; future obligation is not inferred.
- [ ] Activation, partner and unmatched raw-record identities accompany each answer, with complete original item histories.
- [ ] Descriptive rule counts remain separate from a reviewed Norm; normative execution requires an admitted actual Method binding.
- [ ] Multiple-occurrence, equal-time, no-activation, missing-partner and unknown-clock fixtures survive save/restart.
