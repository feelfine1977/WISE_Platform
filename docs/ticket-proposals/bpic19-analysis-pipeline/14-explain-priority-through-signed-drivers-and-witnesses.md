# 14: Explain priority through signed drivers and witnesses

Status: **approved Priority 1 ticket; acceptance expanded on 14 October 2026; implementation qualification remains open**.

Tracker: [116](https://github.com/feelfine1977/WISE_Platform/issues/116) · Parent: [#102](https://github.com/feelfine1977/WISE_Platform/issues/102) · Labels: `priority: first`, `ready`.

## What to build

The analyst opens a priority’s signed layer/criterion explanation on an admitted run, checks coverage and selects a declared exemplar or counterexample with complete source evidence.

## Current platform foundation and missing analyst behavior

Complete item evidence and bookmarks exist. Priority explanations still need signed native layer/criterion terms, reference/coverage context, stable exemplar/counterexample policies and reversible original-row evidence routes.

Audited source frontier: `3d76a578`. New working-tree component tests are separate from qualified public behavior; this section does not assert equivalence with a later or installed candidate.

## Analyst journey

1. Open a frozen native priority
2. Read positive and negative layer/criterion terms
3. Inspect scoped/evaluated/positive/unavailable supports
4. Choose deterministic representative and contrary cases
5. Open exact original evidence
6. Export/save/reopen explanation

## Extended user stories

### T14-S01

As a stakeholder reviewer, I want signed driver terms rather than only the largest positive bars so that offsets explain the actual relative priority.

**Preconditions:** One native backlog/reference fixed

**User actions:**

1. Open group drivers
2. Read signed means and scaled terms
3. Reconcile their sum withPI

**Expected outcome:** Negative terms are retained and the final signed sum is clipped only once.

**Acceptance:** T14-AC01, T14-AC02; the common integration criteria also apply.

### T14-S02

As an analyst, I want prevalence, severity, mass and weighted contribution named separately so that a frequent mild criterion is not confused with a rare severe one.

**Preconditions:** Native deviations/effective weights and eligible supports

**User actions:**

1. Inspect criterion table
2. Compare total/scoped/evaluated/positive denominators
3. Read units

**Expected outcome:** Conditional severity and view-weighted mass have distinct denominators and labels.

**Acceptance:** T14-AC03; the common integration criteria also apply.

### T14-S03

As a reviewer, I want unavailable evidence and each case’s effective weights visible so that favorable timing cannot hide missing clearing or unknown attribution.

**Preconditions:** Whole-case records and local criteria states

**User actions:**

1. Inspect similar to Logistics item
2. Read C02/C04 beside coverage
3. Open missing-resource row

**Expected outcome:** Known absence and unavailable timing/effort remain explicit; coverage is not a compliance score.

**Acceptance:** T14-AC03, T14-AC04; the common integration criteria also apply.

### T14-S04

As an analyst, I want a reproducible exemplar and a contrary item so that the explanation can be challenged against complete records.

**Preconditions:** Declared representative rule and timing admitted if used

**User actions:**

1. Compute the median of all C04-evaluable target items
2. Restrict exemplar candidates to positive deviations
3. Choose nearest to that median with the declared tie rule
4. Open a satisfied or contrary item and its complete source history

**Expected outcome:** Both cases link original raw rows and remain exact frozen members.

**Acceptance:** T14-AC04, T14-AC05; the common integration criteria also apply.

### T14-S05

As a process-improvement expert, I want recommendations separated from the observed drivers so that investigation priority is not presented as proof of cause or implemented savings.

**Preconditions:** Source-labelled descriptive finding

**User actions:**

1. Review interpretation
2. Attach business questions and outside evidence
3. Record proposed/adopted/tested status separately

**Expected outcome:** Source observations, panel recommendation, owner action and measured outcome are separate.

**Acceptance:** T14-AC06; the common integration criteria also apply.

### T14-S06

As a returning reviewer, I want to reopen the same explanation and raw witnesses so that rounding or a later view cannot change the evidence trail.

**Preconditions:** Frozen signed-driver/exemplar artifacts

**User actions:**

1. Export unrounded values
2. Restart
3. Reopen same view and source rows

**Expected outcome:** Signed sums, memberships and original records survive the highest seam.

**Acceptance:** T14-AC07; the common integration criteria also apply.
