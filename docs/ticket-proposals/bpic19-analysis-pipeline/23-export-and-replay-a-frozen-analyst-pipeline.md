# 23: Export and replay a frozen analyst pipeline

Status: **approved Priority 1 ticket; acceptance expanded on 14 October 2026; implementation qualification remains open**.

Tracker: [125](https://github.com/feelfine1977/WISE_Platform/issues/125) · Parent: [#102](https://github.com/feelfine1977/WISE_Platform/issues/102) · Labels: `priority: first`, `ready`.

## What to build

The analyst exports a frozen investigation report and declarative supported-action recipe, then replays/reopens it with the same definitions, evidence and current-run outputs.

## Current platform foundation and missing analyst behavior

Immutable saved Investigations and restart tests are foundations. New profile/measure/operator/run chains and current output manifests still need a supported declarative export/replay contract, integrity checks and real fresh-process reopening.

Audited source frontier: `3d76a578`. New working-tree component tests are separate from qualified public behavior; this section does not assert equivalence with a later or installed candidate.

## Analyst journey

1. Save the currently reviewed investigation/population/operator/native Method run through the existing immutable revision seam.
2. Review the ordered declarative action recipe and operation-admission report before replay.
3. Export a human-readable report, machine-readable recipe and input/output/witness manifest for this run only.
4. Choose all-required replay or a distinctly named partial export/admitted-action replay and inspect omissions.
5. Validate the source/preparation/definition versions and checksums without executing document/notebook instructions.
6. Stop the serving OS process, start a distinct fresh process and reopen exact saved definitions, members, evidence and artifacts.

## Source rules, product decisions and unresolved definitions

- SOURCE: notebook output index is a directory inventory; saved execution order is mixed. Source content is evidence, never executable instructions for the replay engine.
- PANEL DEFAULT: replay schema v1 is a finite ordered list of registered declarative operation names and strictly validated parameters, referring to immutable existing source/preparation/population/operator/Method/model versions. No arbitrary source code or external command text is an action.
- PANEL DEFAULT: require_all admission checks every action before computing a result and refuses if any binding is absent. Explicit partial mode uses a separate recipe/run identity and an omissions manifest with source-method gates; unsupported state alone never claims reproduction of that method.
- PANEL DEFAULT: machine-readable definitions and result values are canonicalized/checksummed; exported artifacts reference only the named current run. Display-only viewport/format changes do not change analytical identity. Frozen referenced output bytes may be reused exactly; rerendering under different fonts/dimensions is not required for binary image equality.
- PANEL DEFAULT: actual process PID1 must terminate before distinct PID2 reopens the workspace; counts/member/row/state/definition IDs compare exactly. Only finite native numerical outputs admit absolute tolerance1e-8. Manual/external human-tool actions need external-run provenance and their own admission, not a substitute calculation.

## Required core and conditional extensions

The named finite panel default plus complete reviewed-input→real HTTP→built-browser→raw-evidence/export/save→actual fresh-PID restart acceptance is required. Source-compatible alternatives are separate identified definitions; unavailable source gates cannot be presented as reproduced methods.

## Extended user stories

### 23-US01

As a research analyst, I want an exported report and declarative recipe tied to one frozen run so that another analyst can reconstruct the same source interpretation and pipeline.

**Preconditions:** Reviewed source and completed supported actions.

**User actions:**

1. Review source/mapping/horizon/profile receipts.
2. Export report/recipe/manifest.
3. Open every witness link.

**Expected outcome:** One coherent run includes exact source/member/operator/method identities and meaningful units.

**Acceptance:** 23-AC01, 23-AC02; the common integration criteria also apply.

### 23-US02

As a software engineer, I want operation admission checked before replay so that unsupported source methods cannot silently run a replacement or arbitrary code.

**Preconditions:** Recipe references supported and unsupported actions.

**User actions:**

1. Choose require_all.
2. Inspect admission refusal.
3. Choose explicit partial mode if desired.

**Expected outcome:** Typed unsupported action and retained source-method gate; no shell/notebook/Python execution.

**Acceptance:** 23-AC03, 23-AC04; the common integration criteria also apply.

### 23-US03

As an analyst, I want the output manifest to contain only current-run artifacts so that old images are not mistaken for evidence produced by the displayed analysis.

**Preconditions:** Shared directory also contains older PNGs.

**User actions:**

1. Export the named current run.
2. Compare manifest artifact IDs/checksums.
3. Inspect stale artifact provenance.

**Expected outcome:** Only current run outputs are included; stale global-directory files are absent.

**Acceptance:** 23-AC02; the common integration criteria also apply.

### 23-US04

As a reviewer, I want changed source bytes or analytical meanings to create new identities so that old results remain auditable instead of being overwritten by new defaults.

**Preconditions:** Saved immutable revisionA exists.

**User actions:**

1. Change source or recipe.
2. Save revisionB.
3. Reopen A and B.

**Expected outcome:** Distinct source/definition/run identities; A remains unchanged and corrupt references refuse.

**Acceptance:** 23-AC05, 23-AC06; the common integration criteria also apply.

### 23-US05

As an analyst returning to the project, I want true fresh-process reopening so that a same-process cache is not the only place where my definitions and witnesses survive.

**Preconditions:** Workspace saved/exported.

**User actions:**

1. Observe original process exit.
2. Start new PID.
3. Reopen matching built browser and compare.

**Expected outcome:** Exact IDs/states/members and finite native values agree within 1e-8; valid outputs/checksums preserved.

**Acceptance:** 23-AC07; the common integration criteria also apply.

### 23-US06

As a process-improvement reviewer, I want limitations and omitted methods included in the report so that reported human findings, current reruns and unexecuted proposals cannot be confused.

**Preconditions:** A supplied literature result and one current platform output coexist.

**User actions:**

1. Review claim levels.
2. Open omitted method gate.
3. Export supported analysis.

**Expected outcome:** Literature claims remain reported/unrerun, current outputs carry run receipts, omitted outputs are explicit.

**Acceptance:** 23-AC04, 23-AC08; the common integration criteria also apply.

## Acceptance criteria

### Approved baseline retained

- [ ] **23-B01.** Reuse existing immutable investigation/run persistence; do not introduce a second finding store.
- [ ] **23-B02.** Exports include definitions, units, grain, support, source/profile/run/calibration and witnesses/limitations.
- [ ] **23-B03.** Only admitted actions execute; missing operators/models return an omission or typed refusal, never arbitrary code.
- [ ] **23-B04.** A current-run output manifest excludes stale charts; changed meanings/source create new identities.
- [ ] **23-B05.** Matching-host browser, actual process stop/restart and exact export/member/answer comparisons prove replay.

### Exact domain and analyst acceptance

- [ ] **23-AC01.** Given a literal fixture with source SHA S, reviewed preparation P, full cases[A,B], selected[A], named recipe D and native run R, when report/recipe/manifest are exported, then every artifact declares S/P/D/R, parent[A,B], selected[A], grainPO-item, clock/horizon, profile/scopes/availability/units and raw witness IDs. The human report, recipe and manifest resolve to the same frozen revision.
- [ ] **23-AC02.** Given current run R generated charts x.png/y.png while a directory also contains old z.png from runQ, when R is exported, then artifact manifest contains exactly[x,y] with R/checksums and excludes z; repeated export of frozen bytes yields the same checksums and no directory glob can add a stale file.
- [ ] **23-AC03.** Given a recipe contains operation notebook_python or shell_command, when replay admission runs, then it is refused unsupported_action before any source code, shell or document instruction executes. Given known declarative actions with invalid/unknown parameters or versions, then a typed field/operator refusal identifies the offending step and no alternate algorithm executes.
- [ ] **23-AC04.** Given actions[read_counts,unavailable_weighted_many_to_many,read_exact_sequence], when require_all replay is requested, then it refuses with step2 and its source/formula gate, without presenting a complete result. Explicit partial mode can execute only admitted steps1/3 and exports omitted_step2, claim_levelpartial and a distinct run identity; it cannot label the report full R13 reproduction.
- [ ] **23-AC05.** Given revisionA on sourceS and definitionD, when one source byte changes, then source/preparation/run identities change; when only a meaning-bearing tie/selector/weight/horizon changes, then definition/run identities change and A remains immutable/reopenable. Changing only viewport leaves analytical identity unchanged.
- [ ] **23-AC06.** Given the saved source/operator/model/output reference is missing or its stored checksum is corrupted, when reopen or replay is attempted, then typed artifact_unavailable/checksum_mismatch is shown and the saved revision is not overwritten or rebound to current defaults; unaffected saved notes/evidence remain available when independently resolvable.
- [ ] **23-AC07.** Given a saved supported run, when original serving PID1 is stopped and its exit is observed, then start distinct PID2, reopen the same workspace in the matching built browser and compare exported prior/current receipts: source/member/row/endpoint/state/definition/run identities equal exactly; finite native values agree within 1e-8; stable stored artifact bytes/checksums agree. A new TestClient object, React remount or browser refresh under PID1 fails this acceptance.
- [ ] **23-AC08.** Given supplied human report findings and current supported output in one report, when exported, then each literature number has source/page/cell and claim_levelreported_not_rerun; each platform number has exact current-run receipt; unavailable source steps include method/version/input/formula gate and omission reason. Existing immutable finding/run persistence is reused and no second finding store is introduced.

### Public behavior, evidence and durability

- [ ] **23-E01.** Given a reviewed definition and frozen parent P, when the analyst executes this ticket's action through the public HTTP API and the matching built browser, then both show the same source/preparation/definition/population identity, exact supporting item IDs, units, availability states and analytical values. A literal independently authored fixture supplies the expected IDs and values; testing a helper against itself is insufficient.
- [ ] **23-E02.** Given an unavailable binding, unsupported policy or unknown input needed by this operation, when the action is requested, then the response and browser provide an explicit typed refusal or criterion-local unavailable state with the offending role/policy/evidence reason. They do not replace it with zero, silently choose another operator, or erase unrelated evaluable evidence.
- [ ] **23-E03.** Given two requests for different definitions or populations, when an older successful response, error or page arrives after the current response, then no old table, graph, evidence action or save payload replaces the current coherent answer. Cancellation and an edited but unreviewed definition prevent publishing the old answer as the new result.
- [ ] **23-E04.** Given a saved answer with source rows and analytical definitions, when the serving process is actually stopped, its exit is observed, a distinct fresh process opens the workspace, and the analyst reopens the investigation, then exact item/row/endpoint IDs, availability states, definitions, comparison roles and stable output identities are unchanged. Finite native numbers agree within absolute tolerance 1e-8; literal counts, membership, scopes and evidence states agree exactly. Reloading a React component or recreating a service object in the same process is not this receipt.
- [ ] **23-E05.** Given saved revision A, when any meaning-bearing definition field identified for this ticket changes, then a new definition or run identity is created and A remains reopenable with its previous settings and values. Changing only presentation order, detail or viewport preserves analytical identity. Missing or checksum-corrupt referenced artifacts produce an explicit refusal and never an automatic overwrite of A under current defaults.
- [ ] **23-E06.** Given a result and one selected supporting, excluded or unavailable item, when the analyst uses the table, keyboard-accessible evidence action or exported reference, then the same complete original item history opens with the exact contributing rows highlighted and the reason for inclusion/exclusion visible. Derived episodes, projections and assessment rows retain their original item/record lineage and never replace the raw history.
- [ ] **23-E07.** Given the current run B after another run A in the same workspace, when B is exported and saved using the current expected investigation revision, then the report and declarative recipe contain B's definitions, memberships, support, evidence, limitations and current output manifest only. An outdated expected revision is refused. Replaying an unknown action/schema/version is refused rather than executing arbitrary supplied code or reusing A's figures.

**Meaning-bearing fields for revision-mutation tests:** source/conversion/preparation lineage, ordered supported-action recipes, input/output/run identities, evidence and current artifacts, schema/implementation versions.

## Required qualification receipts

- Browser interaction on the matching application host, showing reviewed input fields, population, chosen definition, availability and exact source-witness navigation; screenshot/state receipt is separate from source inspection.
- Actual typed HTTP requests and responses from the registered operation, including source/preparation/representation/case-dictionary/population and query revision; independently hand-worked expected values.
- Complete-history evidence receipt: raw row IDs, original cells and all parent item records remain present when an episode, rule activation, signature or temporal peak is inspected.
- Exported frozen definition, source SHA-256, method/profile/operator IDs and versions, parent/selected member IDs or resolvable membership hash, units, availability/support and current-run outputs.
- Immutable investigation revision saved through the existing persistence seam; no second findings store and no executable notebook text in a recipe.
- Actual server OS process stop, wait for termination, start a new OS process, reopen the same workspace in the browser and compare exact saved memberships/definitions/result values/record witnesses/export hashes. A second TestClient, remount, page refresh or same-process cache miss is insufficient.
- Negative requests (wrong population, altered source, unknown definition/version, malformed roles, stale revision) receive typed refusals and never publish as the currently selected answer.

Each receipt identifies the candidate source/build, input and definition identities, independently expected versus actual values, public HTTP and built-browser actions, stable export/save references, observed first-process exit and distinct second-process reopening. Component or synthetic tests do not establish full-source capacity; report the elapsed time, peak memory and output/payload sizes for each full-source action that this ticket requires.

## Remaining gates and closure rule
